# 架构与目录

## 技术现状

应用使用 Tauri 2 作为 Windows 桌面壳，Rust 提供原生保存对话框与单实例能力，界面使用原生 HTML、CSS、JavaScript。项目未使用数据库、后端服务或网络账号系统；数据保存在 WebView `localStorage`。

## 目录职责

| 路径 | 职责 |
| --- | --- |
| `dist/index.html` | 页面结构与模块入口。 |
| `dist/styles.css`、`dist/progress.css` | 页面样式。 |
| `dist/js/app.js` | 事件绑定、应用状态与界面协调。 |
| `dist/js/tasks.js` | 任务、子事项校验、状态联动和排序规则。 |
| `dist/js/storage.js` | 本地状态读取、迁移与保存保护。 |
| `dist/js/backup.js` | JSON 备份创建、校验、导入导出格式。 |
| `dist/js/view.js`、`dist/js/drag.js` | 渲染与指针拖拽。 |
| `src-tauri/src/main.rs` | Tauri 启动、单实例、前端命令注册。 |
| `src-tauri/src/backup.rs` | 备份文件临时写入、同步与落盘。 |
| `tests/` | 不接触真实数据的 Node 行为测试。 |

## 启动与数据流

Tauri 启动后加载 `dist/index.html`，该页面引入 `app.js`。`app.js` 通过 `storage.js` 优先读取 `task-list-state-v2`；如不存在则尝试读取旧键 `task-list-v1` 和 `task-list-memo-v1` 并迁移。任务操作生成候选状态，只有 `saveState` 成功后才更新页面状态。

导出时前端生成 JSON，再通过 `save_backup` 命令请求 Rust 打开保存窗口；Rust 先写同目录临时文件并同步，避免直接覆盖旧备份。导入在前端完整校验后，作为一次新的状态保存。

## 数据边界与限制

- 源码：`dist/`、`src-tauri/`、测试和文档，应提交。
- 生成物：`node_modules/`、`src-tauri/target/`、`src-tauri/gen/`，不提交。
- 用户数据：WebView 本地存储与用户导出的 JSON 备份，不提交。
- 物理本地存储目录不是当前项目承诺的稳定接口；可靠恢复方式是应用内 JSON 备份。
- 当前没有移动端适配、云同步、账号、数据库或自动更新功能。

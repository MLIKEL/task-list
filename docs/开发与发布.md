# 开发与发布

## 环境与运行

已验证环境：Windows、Node.js 22、Rust MSVC 工具链、WebView2 Runtime。

从新克隆仓库开始：

```powershell
npm install
npm test
npm run tauri:build
```

- `npm test`：已验证，运行 `tests/` 中的 Node 行为测试。
- `npm run tauri:build`：已验证，生成 NSIS 安装包。
- 安装包路径：`src-tauri/target/release/bundle/nsis/任务清单_<版本>_x64-setup.exe`。
- 前端应修改 `dist/`，不要修改 `src-tauri/target/` 里的生成文件。

## 版本与发布

版本号必须在以下文件保持一致：`package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json`。标签规则为 `v<版本>`，例如 `v1.0.3`。

发布前顺序：导出个人数据备份 → 运行测试 → 构建安装包 → 核对版本和安装包文件名 → 提交并推送源码 → 创建指向该提交的标签 → 创建 GitHub Release 并上传 NSIS 安装包 → 核对 Release 资产与下载链接。

## GitHub Actions

`.github/workflows/build-windows.yml` 会在推送到 `main` 且命中 `dist/index.html`、`src-tauri/**` 或 `package.json` 时构建 Windows 安装包并保留 30 天 Artifact；它**不会自动创建 Release**。该工作流的路径过滤尚未覆盖 `dist/js/**` 和样式文件，见 [当前状态](当前状态.md) 的 P2。

`.github/workflows/publish-v1.0.2.yml` 是历史一次性发布流程，只针对 v1.0.2；不要复用或修改为新版本，除非当次任务明确授权。

## 常见情况

- `gh` 命令不存在：可使用网页 GitHub Release 界面，或安装并登录 GitHub CLI；本项目不依赖它运行。
- 备份提示同名文件存在：选择新的文件名，应用不会覆盖旧备份。
- 本地修改只涉及 `dist/js/`：当前 Actions 不会自动构建，需本机执行构建或先完成 P2。
- 安装前关闭旧版程序；若第二次启动只聚焦已有窗口，属于单实例设计。
